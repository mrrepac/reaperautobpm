# Detect beat BPM — UX доработка

Дата: 2026-08-18
Статус: реализовано, версия 1.3.0

## Контекст

Action `Detect beat BPM and set project tempo.lua` v1.0.0 работал: определял BPM выделенного item
через Essentia и выставлял темп проекта. Претензий к точности не было, претензии к взаимодействию.

Что мешало:

1. Темп применялся молча. Результат нельзя было посмотреть до применения и нельзя было поправить,
   если Essentia услышала half-time не так, как нужно. Откат только через Ctrl+Z.
2. Требовался ровно один выделенный item, иначе ошибка.
3. Временные файлы `bpm_result_*.txt` оставались в `engine/`, если анализ прерван
   (закрытие REAPER, Escape — Escape останавливает defer-циклы).

## Решение

Поток действия:

```text
кнопка
  → выбрать item (выделение → edit-курсор → единственный audio item в проекте)
  → BPM из metadata/имени файла, иначе фоновый Essentia
  → диалог подтверждения с подставленным BPM
  → применить темп проекта
```

Путь через metadata больше не применяет темп молча — оба пути сходятся в один диалог.

### Выбор item

Приоритет, первое сработавшее выигрывает:

1. Ровно один выделенный audio item.
2. Выделено несколько → ошибка. Скрипт не угадывает, какой из них бит.
3. Ничего не выделено → audio item, накрывающий edit-курсор. Если таких несколько,
   приоритет у item на выбранном треке; иначе берётся верхний по порядку треков.
4. Иначе → если в проекте ровно один audio item, берётся он.
5. Иначе → сообщение с подсказкой.

Позиция мыши не используется: при вызове с тулбара курсор находится над кнопкой,
и результат был бы непредсказуем.

### Диалог

`reaper.GetUserInputs`, одно поле `BPM:`. Заголовок несёт происхождение значения
(`Detected 70 BPM (raw 139.93, conf 2.70)` либо `(metadata ID3:TBPM)`).
Enter применяет, Cancel отменяет полностью — темп не трогается.

Темп целый. Найденное значение округляется до целого перед показом, введённое вручную —
перед применением. Валидация: число в диапазоне 20–960, иначе явное сообщение.

Заголовок также выписывает половинный и удвоенный уровни:
`Detected 140 BPM (half 70 / double 280, conf 2.70)`.

### Тишина вместо консоли

Скрипт не пишет в ReaScript console вообще. Окно консоли всплывает поверх работы и выглядит
инородно, а единственное, что оно сообщало по делу, теперь несёт заголовок диалога.
Ошибки идут обычным `reaper.MB`.

### Полировка

- **Двойной запуск.** Флаг в `ExtState` (непостоянный) с меткой времени `os.time()`.
  Второй запуск сообщает, что анализ уже идёт. Метка нужна, чтобы флаг не залипал,
  если предыдущий прогон убит Escape.
- **Мусор.** Файлы `bpm_result_*` в `engine/` молча удаляются при старте анализа.
  Имена сначала собираются, потом удаляются — перечисление каталога не мутируется на ходу.
- **Undo.** Смена темпа идёт одним блоком, `C_BEATATTACHMODE` выставляется в 0,
  чтобы item не растянулся вслед за темпом.

### Структура

Один Lua-файл. Односоставная установка (перетащил файл — готово, совместимо с ReaPack)
для REAPER-экшена ценнее разбиения на модули.

Попутно приведена в порядок `engine_paths`: раньше функция возвращала четыре значения
и передавала путь launcher в слоте ошибки. Стала `table, error_message`.

## Что было отвергнуто

**Сдвиг item на долю.** Версия 1.1.0 двигала item так, чтобы первый beat tick Essentia
попадал на ближайшую долю нового темпа. На практике в REAPER это не дало полезного результата
и было убрано целиком вместе с разбором ticks. Item не двигается ни при каких условиях.

**Прогресс в консоли.** Версия 1.1.0 дописывала точку в ReaScript console раз в секунду.
Убрано вместе со всем консольным выводом.

**Дробный BPM.** Версия 1.1.0 округляла до десятых. Значения вида 70.1 бесполезны
для этого материала.

**Свёртка метрического уровня.** Версии до 1.3.0 приводили результат к окну 55–110 BPM,
чтобы 140 становилось 70. Окно со отношением 2:1 однозначно отображает любой темп, но
обслуживает ровно один жанр. На треке `Audiio_JustinMorgan_APlaceCalledHome` Essentia выдала
112.746 BPM при истинных 113.00 — свёртка превратила это в 56, промах ровно вдвое.
Никакой выбор границ не решает обе задачи одновременно:

| Окно | 139.9 BPM | 112.7 BPM |
|---|---|---|
| 55–110 | 70 | 56 |
| 70–140 | 140 | 113 |

Свёртка убрана. Уровень предлагается как услышан, а соседние выписаны в заголовке.

## Проверка

Автоматическая: харнесс на fengari (Lua VM под Node) с замоканным reaper API прогоняет
исходник скрипта целиком — 51 проверка, включая применение, отмену, ручной ввод, округление,
все ветки выбора item, метаданные, чистку файлов, защиту от двойного запуска и ошибки движка.
Харнесс живёт вне репозитория.

Ручная, в REAPER, на `beat.mp3` (Essentia даёт 139.932, confidence 2.7 → 140 BPM):

1. Выделенный item → диалог показывает 140 и подсказку `half 70` → Enter → темп 140, item на месте.
2. В диалоге 140 заменяется на 70 → применяется 70.
3. Cancel → темп проекта не изменился.
4. Ctrl+Z один раз → откат темпа.
5. Ничего не выделено, курсор на item → item находится.
6. Выделены два item → понятная ошибка, анализ не запускается.
7. Повторный запуск во время анализа → сообщение о том, что анализ уже идёт.
8. После прогона в `engine/` не остаётся `bpm_result_*`.
9. ReaScript console не открывается.
